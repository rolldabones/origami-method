## How the Origami Method works

We build the workflow the way you fold paper: deliberately, one crease at a time, testing as we go.

| Metaphor | Plain meaning | What it means for your workflow |
|---|---|---|
| **Sheet** | Project materials | Goal, inputs (the published notes), people and limits |
| **Creases** | Input/output rules | What acceptable notes look like, and the fixed structure of the action list |
| **Folds** | Controlled change | Small, logged edits to the workflow after testing |
| **Unfolding** | Test and fix | Running test cases and inspecting failures |
| **Lock** | Freeze | Making a proven step mandatory |
| **Expose** | Reveal | Adding checks that show where failures happen |

**Path:** Target → Context Packet → Risk → Data Handling → Creases → Base Workflow → Gates → Roles → Export Readiness → Testing → Folds.

**Two rules that matter for an organization:**
1. **Approvals of record:** Risk & RACI, Data Handling, Design and Release approvals must name the approver, the artifact and version, the date and the word "approved." A chat "yes" moves us to the next stage but is not an approval.
2. **Single workflow:** This session covers one workflow only, from notes to reviewed action list. Related workflows, such as distributing the list or tracking completion, would be separate sequential runs.
