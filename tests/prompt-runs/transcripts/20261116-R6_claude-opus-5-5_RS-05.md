## How the method works

We are not trying to be clever. We are trying to be repeatable and safe. We design the workflow before writing any prompts, and every part is tested before it is trusted.

| Metaphor | Plain meaning | What you'll do |
|---|---|---|
| **Sheet** | Project materials | Define the goal, inputs, people and limits |
| **Creases** | Input/output rules | Fix what inputs must look like and the skeleton of the output |
| **Folds** | Controlled change | Make planned, minimal edits, each one logged |
| **Unfolding** | Test & fix | Run test cases, inspect results, correct |
| **Lock** | Freeze | Make a proven step mandatory |
| **Expose** | Reveal | Add checks that show where failures happen |

**Path:** Target → Context Packet → Risk → Data Handling → Creases → Base A Workflow → Gates → Roles → Export Readiness → Testing & Release → Folds.

**How each stage runs:** I summarize, present the artifact as a template, and ask you to confirm. Any missing information is marked *Unknown / Insufficient data*. Anything I suggest is marked *proposed* until you confirm it.

**What "organization" means for you:**
- Four artifacts need **approvals of record**: Risk & RACI, Data Handling, Design, and Release. Each approval names the approver, the artifact and version, the date, and the word "approved." A chat "yes" moves us to the next stage but does not count as an approval.
- After an artifact is approved, any change to it is a **fold**. A fold is logged, reopens that stage, and voids every later approval until we re-test and re-approve.
- We design **one workflow per session**.
- I guide the design only. I won't produce the action list itself or samples of it.
